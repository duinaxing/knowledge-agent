# 100 人压测工具交付与首次验证

## 已执行

- 隔离数据库 `knowledge_loadtest_100`，独立端口 8100–8102。
- 100 员工、10 用户组、300 文档、330 个已索引版本、20000 轮预置历史。
- 模拟模型冒烟：独立登录、功能/幂等/权限检查、100 人短时读取、100 人集中提问、重新登录、集中登录限流。
- 4 人故障探针：模型延迟、429、超时、测试 worker 重启和恢复。
- 后端完整回归 128 项通过；后续增加网关请求关联检查，压测工具专项共 9 项。

## 首轮实测

| 项目 | 结果 |
|---|---|
| 100 人集中发送跨度 | 0.031 秒，满足 1 秒内发出 |
| 问答提交 | 100/100 成功，P95 0.906 秒 |
| 最终有效回答 | 42/100；其中 41 个端到端耗时 ≤60 秒 |
| 总耗时 P95 | 61.484 秒，包含失败请求 |
| 排队 P95 | 60.953 秒（仅已被领取的任务；未领取为缺失值） |
| 100 人短时读取 | 100% 成功，P95 0.609 秒 |
| 8 秒模型延迟探针 | 4/4 有效回答，P95 25.641 秒 |
| 模型 429 / 超时 | 均返回明确失败，不误算有效回答 |
| worker 重启 | 4/4 通过 resume 恢复并有效回答，P95 21.406 秒 |
| 各阶段结束后恢复检查 | 队列清空，读取延迟恢复到目标内 |
| 真实 DeepSeek 调用 | 0 次 |

本轮结论：默认 4 槽位、60 秒期限下，未达到“100 人集中提问至少 95 个按时回答”的目标。提交和读取基本稳定，问答排队耗尽期限是主要现象，不能通过 HTTP 202 的 100% 成功率认定问答容量达标。

原始首轮端到端时间包含取得最终回答后引用及历史核对的少量耗时；后续脚本将该核对耗时独立保存为 `validation_seconds`。本轮数据不作回写修饰。
