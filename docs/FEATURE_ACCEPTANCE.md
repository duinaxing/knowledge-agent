## 历史与权限规则

- 用户自己的问题永久保留，历史回答保留当时内容与引用快照；历史内容不代表最新事实。
- 每次读取历史重新检查引用对应项目/文档的当前权限。任一来源已删除或无权访问时，整条回答正文和引用隐藏，问题仍保留。
- 知识 epoch 更新后，原会话仍可查看、继续提问。继续提问重新绑定当前 epoch、清空旧项目选择；不同 epoch 的旧回答不会进入模型上下文。
- 正在运行的任务若遇到权限变化仍停止，SSE 事件不直接携带答案正文。旧执行检查点按原策略清理，不再清理用户聊天记录。
- 改密要求输入旧密码，成功后包括当前设备在内的全部登录会话失效，重新登录即可找回聊天。

## 已落实的性能措施

1. SQL 中过滤用户/用户组授权并取项目和文档权限交集，消除逐文档 ACL 查询。
2. PostgreSQL 内用 pgvector 计算授权版本中的余弦距离，仅返回前 20 个向量候选，不再把全部向量传回 Python。当前为精确检索，尚未启用 ANN。
3. 中文分词 LRU（4096 项）和有容量限制的 BM25 索引缓存（8 个授权语料集合）；缓存只在权限过滤后使用，不缓存最终答案。
4. 会话/消息分页，所有权与时间复合索引、版本和队列状态索引；管理员文档列表批量读取版本，消除逐文档版本查询。
5. PostgreSQL 默认 4 个问答并发槽位，另有 1 个文档处理槽位；每个问答槽使用独立检查点连接。SQLite 仍单 worker 演示。
6. 持久租约、领取代次、幂等键、超时和调用预算；模型输入另限 64000 UTF-8 字节（资源上限，不冒充精确 token 数）。
7. 数据库原子共享限流：登录每 IP 每分钟 30 次，注册 10 次，改密每用户 10 次，提问每用户 20 次；跨 API 进程生效。使用固定分钟窗口。
8. SSE 的持续数据库轮询在线程中执行，避免同步数据库查询阻塞事件循环；管理页显示排队、运行及失败计数。
9. 密码 scrypt 哈希、HttpOnly Cookie、CSRF/Origin 校验、后端管理员鉴权、请求编号和敏感信息脱敏日志。

## 部署与验证边界

新增迁移 0002，启动前执行 `python -m knowledge_agent.bootstrap --migrate`。本次迁移前已生成 runtime/backups/knowledge-20260913-212255.dump；备份含用户及会话，应留在受控本地存储。可用 PostgreSQL pg_restore 恢复到独立空数据库并校验后再切换连接，避免覆盖现库。

环境参数：WORKER_CONCURRENCY 默认 4（1–8），MAX_CONTEXT_BYTES 默认 64000。增加 worker 前须确认模型并发配额和数据库连接容量。公开部署应配置 HTTPS 和 COOKIE_SECURE=true，并为域名配置 ALLOWED_ORIGINS。

本次验证包含前端自动交互测试与真实 HTTP 全链路；浏览器控制连接不可用，未声称完成新版界面的人工视觉验收。尚未验证跨机器高可用、自动故障切换、长期峰值负载、百万片段检索和异地备份恢复演练；这些需要目标硬件、数据规模和可用性指标，不能把“使用了优化技术”当作这些指标已达成。
# 文档多选与用户组员工管理（2026-09-14）

- 文档库点击“选择文档”进入多选模式，可逐份勾选或全选已加载文档；超过首批 100 份时先加载更多，再选择。单次最多删除 1000 份，确认框显示数量；已删除文档不可选择。
- 批量删除接口仅管理员可用，全部 ID 校验后在一个事务中删除，沿用原有权限失效、历史引用保护与后台文件清理机制。请求重试不重复创建清理任务。
- 用户组点击“管理员工”，按姓名或用户名搜索；“组内员工”可移出，“可添加员工”可加入。操作立即保存，不删除用户账号，不影响员工的其他用户组关系。
- 员工管理使用逐人增删接口并锁定用户组，避免整组覆盖其他管理员的成员修改；保留原批量成员接口兼容性。
