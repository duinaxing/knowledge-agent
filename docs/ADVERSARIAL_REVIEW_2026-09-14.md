# 对抗性审查报告 · 2026-09-14

## 结论与范围

对账号/CSRF、管理员接口、项目与文档 ACL、会话和历史、通用回答与 RAG、上传/解析、模型异常响应、后台任务、并发授权、前端异步状态进行了源码审查和隔离测试。发现并修复下列问题；没有将通过测试表述为“没有任何漏洞”。

测试使用独立 knowledge_test_project2_20260912 数据库和临时文件。未对现有业务用户、用户组、项目或文档执行攻击性删除或权限修改。真实 DeepSeek 测试使用三条合成提示注入文本，没有发送真实业务文档或密钥。

## 发现与处理

| 编号 / 优先级 | 触发与影响 | 修复 / 证据 |
| --- | --- | --- |
| A1 / P1 | 通用回答可能复述模型上下文中的项目名/历史信息，却没有引用；撤权后历史检查只看 evidence，仍可显示。澄清候选也存在同类遗漏 | 为生成答案保存模型输入的 access_scope，历史读取重新检查范围与候选权限。缺少该字段的旧通用回答在 epoch 改变后隐藏；两个测试修复前失败、修复后通过 |
| A2 / P1 | 工具因越权失败后，模型返回 intent=general 可绕过“缺少证据”的失败处理；明确项目问题也可被模型自标通用 | 有工具错误时禁止通用兜底；明确命中项目/文档的问题若被标通用，返回 EVIDENCE_REQUIRED。保留正常通用对话和带证据问答；越权兜底测试修复前失败 |
| A3 / P1 | 点击原文后立即切换会话/退出，旧请求稍后返回仍可设置证据面板；提交中的旧请求也可能重开旧监听 | 为原文、提交、分页与权限失效增加请求代次检查；账号失效清空反馈等状态。两个延迟 Promise 前端用例通过 |
| A4 / P2 | 大请求先进入 JSON/multipart 解析，文件大小检查发生过晚；伪造 Content-Length 或流式正文缺少统一限制 | 解析前按声明与实际字节双重限制：普通请求 64 KiB，上传为文件上限加 256 KiB；接收总时限 20 秒。两个修复前失败用例通过 |
| A5 / P2 | 文件先落盘、数据库事务后失败，遗留无记录原件，可累积占用磁盘 | 事务记录本次创建文件，异常/提交失败时清理；强制回滚测试修复前失败、修复后通过 |
| A6 / P2 | 模型 message=null 或数组触发非受控异常，产生 INTERNAL_ERROR 而非可理解失败 | 校验 message 为对象，统一归为 INVALID_MODEL_RESPONSE；四种畸形响应中原先两种失败，现全部通过 |
| A7 / P2 | 检查用户组存在后，组可能被并发删除；授权写入可能留下不存在主体的 ACL | 授权时锁定主体，按固定顺序取锁；真实 PostgreSQL 测试确认删除等待授权事务结束，最终无组也无残留组授权 |
| A8 / P2 | 普通读取跨多个查询，权限检查与响应之间缺少最终 epoch 复查 | 项目列表、历史、原文读取刷新身份并在返回前复查 epoch；注入读取期间 epoch 变化，返回 409 而非旧项目内容 |

P1 表示优先处理的权限/隔离风险，P2 表示可靠性或资源边界问题。本表是本项目的修复优先级，不是经过外部机构评定的 CVSS。

## 保留的功能与处理边界

注册/登录/改密、用户组增删、项目增删改与编号复用、文档预览与版本发布、通用问答、RAG、历史、会话删除等继续由现有回归覆盖。账号密码与现有权限配置未调整。

access_scope 采用保守策略：模型输入中任一来源失去访问权，整条历史回答会隐藏，即便无法证明该来源实际影响了输出；记录仍保存。界面会说明上下文权限变化。这避免把“无引用”误当成“无企业信息”。

## 尚未解决或未覆盖的风险

1. 模型语义层提示注入、真假事实和引用支持度无法靠 JSON/白名单完全证明。三条真实样例只是抽样；不包含无限变体、多语言诱导和长期多轮红队。未知内部对象若被错误判为通用，仍有幻觉风险，但模型没有越权读取工具权限。
2. 输入目录仍有 200 条上限，检索采用精确排序。百万文档、持续高并发和资源隔离需要专门规模测试。
3. 请求大小上限不代替反向代理的连接数/速率限制。公开注册可产生账号和存储增长，现有分钟限流不等于全站计费额度或抗 DDoS。
4. Windows 解析进程有超时但不是完整操作系统沙箱。进程突然崩溃或 unlink 失败仍可能留下原件，需要离线孤儿文件巡检；本次只修复正常事务回滚路径。
5. 已配置的演示密码 123456 按用户要求保留；公开部署需要另行配置凭据、HTTPS、安全 Cookie 与备份访问控制。
6. 尚未执行 Python/全部开发依赖漏洞库审查、跨机器高可用或备份恢复演练。没有声称整个依赖链无漏洞。
7. 本次没有浏览器视觉人工验收；前端证据来自自动交互测试。删除会话不意味着备份和所有旧检查点被即时物理擦除。

## 复现

在 project 下设置 TEST_DATABASE_URL 指向名称以 knowledge_test_ 开头的专用测试库，然后执行 `python -m pytest backend/tests -q -p no:cacheprovider`。该测试会重建测试库表，禁止指向业务数据库。前端执行 `npm --prefix frontend test -- --run` 与 `npm --prefix frontend run build`。
